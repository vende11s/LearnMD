# Verification record

## Shared bundle parser denial-of-service fix — 13 October 2026

A follow-up review found a gap in the initial sharing review: individually valid notes with repeated headings could stall the receiver during synchronous validation. Five notes containing `'# Repeat\n\n'.repeat(9000)` total 450,000 source bytes. On the same local machine, direct parsing of this corpus took 15,009 ms before the fix and 1,269 ms after it. These are diagnostic measurements, not response-time guarantees. A 4,999-heading note within the new aggregate line budget took 163 ms after the fix.

The fix uses per-slug suffix cursors, preserving semantic ID collision behavior while removing repeated suffix searches, and appends synchronization-group members without repeatedly copying earlier arrays. A raw-source admission check rejects oversized combined character, logical-line, or Markdown-delimiter counts before parsing the first note, on both sender and recipient paths. The 450 KB corpus is now rejected before any Markdown parse. Images retain their separate byte budget. Parsing and rendering remain synchronous for accepted content; the aggregate limits bound work rather than guaranteeing uninterrupted frames on every device.

Local verification passed 358 unit tests across 21 files, the TypeScript/production build, skill-reference consistency, and all 10 desktop/mobile sharing browser scenarios. Regressions cover deterministic linear collision work, natural/explicit ID conflicts, CR/LF/CRLF, limits exceeded only by the last note with zero parser calls, image-heavy valid content, unchanged data after rejection, localized guidance, and normal local reading after rejecting the malicious share. An independent read-only review also compared 10,000 mixed collision sequences against the original ID allocator without a mismatch.

This is a browser-runtime failure before the application loads. Firefox verification was completed successfully on the Ubuntu GitHub Actions runner instead. The Firefox project remains configured; run `npm run test:e2e -- --project=firefox` on a host with a functioning Firefox runtime.

The application relies on standard IndexedDB, file inputs, native controls, and optional directory input. It does not depend on Chromium's File System Access API. Directory selection and persistent-storage grants depend on the browser.
